# 서울 자치구 경계 기반 Map-first 리스크 탐색 UX

## 1. 프로젝트 개요

Redveil V2는 기존 Redveil V1의 보류 우선 의사결정 흐름을 확장해, 사용자가 서울 25개 자치구의 리스크 지형을 실제 지도 형태로 탐색하고, 관심 구를 선택한 뒤 매물 검토·후보 비교·보류 메모 작성으로 자연스럽게 이동할 수 있도록 만드는 지도 중심 제품 개선 버전이다.

기존 V1이 “매입 전 보류 사유를 먼저 확인하는 정적 리스크 진단 프로토타입” 이었다면,
V2는 “서울 리스크 지형을 먼저 훑고, 관심 후보를 구체적인 검토 흐름으로 연결하는 Map-first 의사결정 UX”를 목표로 한다.

이번 달의 핵심 목표는 실제 지도 API 기반 서비스 완성이 아니라, GitHub Pages에 배포 가능한 정적 인터렉티브 지도 기반 V2를 구현하는 것이다.

---

## 2. V2 목표 구분

### 2.1 이번 달 목표

이번 달 V2의 목표는 다음과 같다.

> 지도 기반 탐색 → 관심 구 선택 → 보류 사유 확인 → 매물 검토/후보 비교로 이어지는 흐름을 구현한다.
> 

구체적으로는 기존 추상 지도 UI를 실제 서울 자치구 경계 기반 지도형 화면으로 개선하고, 선택한 구가 Redveil의 기존 기능인 매물 검토, 후보 비교, 구별 리포트와 연결되도록 한다.

### 2.2 최종 목표

장기적으로는 실제 지도 라이브러리 또는 지도 API 기반의 서비스형 UX까지 확장한다.

최종 목표는 다음과 같다.

> Leaflet, Kakao Map, Naver Map 등 지도 라이브러리/API를 활용해 확대·축소, 주소 검색, 위치 기반 후보 탐색, 매물 마커, 주변 상권 레이어까지 확장 가능한 지도형 의사결정 서비스로 발전시킨다.
> 

다만 최종 목표는 이번 달 구현 범위에 포함하지 않는다. 이번 달에는 실제 행정구역 경계 데이터를 활용한 정적 인터랙티브 지도 MVP를 우선 완성한다.

## 3. 문제 정의

서울 소형 상가 매입 후보를 검토하는 사용자는 특정 구나 매물을 이미 염두에 두고 있는 경우가 많다. 그러나 기존 정보는 가격, 거래량, 상권 밀도, 수요 취약도, 대체 후보를 한눈에 비교하기 어렵고, 의사결정 전에 “왜 멈춰야 하는지”를 구조화해주지 못한다.

Redveil V1은 이 문제를 보류 사유 중심의 리스크 진단 흐름으로 해결했다. 하지만 V1의 지도 영역은 실제 서울 경계 기반 지도가 아니라 추상화된 리스크 그리드에 가까웠기 때문에, 사용자가 “서울의 어느 지역이 어던 리스크 지형에 놓여 있는지”를 직관적으로 이해하는 데는 한계가 있다.

V2는 이 한계를 보완한다. 사용자는 입력 폼에서 바로 출발하는 대신, 실제 서울 자치구 경계 기반 지도에서 리스크 지형을 먼저 확인하고, 관심 구를 선택한 뒤 다음 행동으로 이동한다.

---

## 4. 핵심 사용자

Redveil V2의 핵심 사용자는 다음과 같다.

1. 서울 소형 상가 매입 후보를 검토하는 개인 투자자
2. 특정 구나 매물에 관심이 있지만, 중개사의 설명을 데이터 기준으로 확인하고 싶은 사용자
3. 현장 답사 전에 가격 부담, 거래 유동성, 상권 과밀, 수요 취약도 등을 빠르게 훑고 싶은 사용자
4. “어디가 좋다는 추천보다 “어떤 이유로 보류해야 하는가”를 먼저 알고 싶은 사용자

---

## 5. V2 핵심 콘셉트

### 5.1 한 줄 정의

Redveil V2는 서울 자치구 경계 기반 지도에서 리스크를 탐색하고, 선택한 구를 매물 검토와 후보 비교로 연결하는 Map-first 의사결정 UX이다.

### 5.2 제품 방향

Redveil V2는 투자 추천 서비스가 아니다.

사용자에게 “어디를 사야 하는지”를 알려주는 것이 아니라, “어떤 조건에서 멈추고 비교해야 하는지”를 먼저 보여준다.

따라서 V2의 핵심 방향은 다음과 같다.

- 추천보다 보류 사유 우선
- 점수보다 판단 근거 우선
- 단일 후보보다 대체 후보 비교 우선
- 확신보다 현장 확인 질문 우선
- 지도 탐색에서 검토 메모까지 이어지는 흐름 우선

---

## 6. 이번 달 구현 범위

이번 달 구현 범위는 지도 구현 1~3단계로 제한한다.

### 6.1 1단계: 실제 서울 자치구 경계 지도 적용

기존 추상 지도 대신 서울 25개 자치구 경계 데이터를 활용한 지도형 화면을 구현한다.

구현 항목:

- 서울 자치구 경계 GeoJSON 또는 SVG 데이터 확보
- 구 이름 또는 구 코드 기준으로 Redveil 리스크 payload와 매칭
- 구별 riskScore에 따른 시각적 등급 표현
- 기존 Redveil 다크 톤에 맞는 지도 스타일 적용
- GitHub Pages에서 동작 가능한 정적 파일 구조 유지

### 6.2 2단계: 지도 상호작용 구현

사용자가 지도에서 구를 직접 선택하고, 선택 결과가 오른쪽 리포트나 상세 영역에 반영되도록 한다.

구현 항목:

- 구 hover 시 구 이름과 리스크 점수 표시
- 구 click 시 선택 구 변경
- 선택된 구 강조 표시
- 리스크 등급별 시각 구분
- 지도 범례 제공
- 모바일 환경에서 지도 영역 깨짐 방지

### 6.3 3단계: 기존 기능과 연결

지도에서 선택한 구를 Redveil의 기존 검토 흐름으로 연결한다.

구현 항목:

- 선택 구에서 `매물 검토로 이동` 버튼 제공
- 선택 구에서 `후보 비교로 이동` 버튼 제공
- 대체 후보와 비교하는 CTA 제공
- URL 파라미터를 통해 review/compare 화면에 선택 구 전달
- 사용자가 지도 탐색 후 바로 보류 메모 또는 비교 메모로 이어질 수 있도록 흐름 정리

---

## 7. 이번 달 제외 범위

이번 달에는 다음 기능을 구현하지 않는다.

- Leaflet/Kakao/Naver 지도 API 기반 확대·축소 지도
- 주소 검색
- 실제 매물 위치 마커
- 지번 또는 도로명주소 기반 검색
- 지하철역, 버스정류장, 유동인구 등 추가 지도 레이어
- 실시간 데이터 업데이트
- 백엔드 기반 사용자 계정/저장 기능
- 투자 추천, 매수 추천, 수익률 예측 기능

이 기능들은 최종 목표 또는 후속 버전의 확장 범위로 둔다.

---

## 8. 사용자 흐름

V2의 기본 사용자 흐름은 다음과 같다.

1. 사용자가 Redveil 홈에 진입한다.
2. 홈에서 “서울 리스크 지도에서 시작하기”를 선택한다.
3. 서울 25개 자치구 경계 기반 리스크 지도를 확인한다.
4. 관심 있는 구를 클릭한다.
5. 선택 구의 리스크 점수, 보류 사유, 주요 위험 축, 대체 후보를 확인한다.
6. 사용자는 다음 중 하나를 선택한다.
    - 이 구로 매물 검토 시작
    - 대체 후보와 비교
    - 구별 리포트 더 보기
7. 매물 검토 또는 후보 비교 화면으로 이동한다.
8. 사용자는 보류 판단, 현장 확인 항목, 대체 후보, 검토 메모를 남긴다.

## 9. 핵심 화면 구성

### 9.1 Home

역할: V2의 진입점

추가 또는 개선 항목:

- “서울 리스크 지도에서 시작하기” CTA 제공

- “후보 비교하기” CTA 제공
- V2가 지도 중심 흐름이라는 점을 첫 화면에서 설명

### 9.2 Districts

역할: V2의 핵심 화면

개선 항목:

- 실제 서울 자치구 경계 기반 지도 표시
- 구별 리스크 색상 적용
- 선택 구 강조
- 선택 구 리스크 요약 표시
- 보류 사유, 대체 후보, 현장 확인 항목 표시
- 매물 검토/후보 비교로 이동하는 버튼 제공

### 9.3 Review

역할: 선택 구를 기반으로 매물 검토 메모 생성

개선 항목:

- URL 파라미터로 전달된 구 자동 선택
- 선택 구의 리스크 요약 표시
- 저장 메모에 구 이름, 위험 등급, 주요 보류 사유 표시
- 저장된 후보를 비교 화면으로 보낼 수 있는 버튼 추가

### 9.4 Compare

역할: 선택 후보와 대체 후보를 같은 기준으로 비교

개선 항목:

- URL 파라미터로 후보 A/B/C 자동 선택
- 지도에서 선택한 구와 대체 후보를 비교하도록 연결
- 비교 결과를 보류 메모 형태로 정리
- 사용자가 “확정”보다 “비교 후 판단”하도록 흐름 유지

## 10. 데이터 및 기술 구조

### 10.1 지도 데이터

필요 데이터:

- 서울 25개 자치구 경계 GeoJSON 또는 SVG
- 구 이름
- 구 코드
- 좌표 정보
- 데이터 출처 및 라이선스 정보

확인할 사항:

- 공개 사용 가능 여부
- 출처 표기 방식
- 좌표계
- 파일 크기
- GitHub Pages에서 로드 가능한 정적 파일 형태인지 여부

### 10.2 Redveil 리스크 데이터

기존 Redveil payload의 구별 리스크 데이터를 활용한다.

매칭 기준:

- 구 코드 우선
- 구 코드가 불안정할 경우 구 이름 보조 매칭
- riskScore, riskGrade, riskArchetype, objections, replacementCandidates 등 기존 필드 재사용

### 10.3 프론트엔드 구조

예상 파일 구조:

```
app/site/assets/seoul-districts.geojson
app/site/districts.html
app/site/districts.js
app/site/css/redveil-districts.css
app/site/website_payload.js
```

핵심 구현 방식:

```
1. seoul-districts.geojson 로드
2. 각 구 feature와 Redveil payload 매칭
3. riskScore에 따라 지도 스타일 적용
4. 지도 path 클릭 시 selectedDistrict 변경
5. 기존 district detail 렌더링 함수와 연결
6. review.html / compare.html로 선택 구 전달
```

## 14. 리스크 및 대응

### 14.1 지도 데이터 라이선스 문제

리스크: 사용할 수 없는 지도 데이터를 가져오면 포트폴리오 공개에 문제가 생길 수 있다.

대응:

- 공공데이터 또는 공개 라이선스 데이터만 사용
- README에 출처와 라이선스 명시
- 불확실한 데이터는 사용하지 않음

### 14.2 파일 크기 문제

리스크: GeoJSON 파일이 너무 크면 GitHub Pages 로딩 속도가 느려질 수 있다.

대응:

- 자치구 단위 경계만 사용
- 좌표 단순화 버전 사용
- 필요 시 SVG 변환 또는 경량화 처리

### 14.3 구현 범위 확장 문제

리스크: 지도 API, 주소 검색, 매물 마커까지 욕심내면 이번 달 안에 완성도가 떨어질 수 있다.

대응:

- 이번 달은 1~3단계로 제한
- Leaflet/Kakao/Naver 지도는 최종 목표로 문서화
- MVP 기준을 먼저 충족한 뒤 후속 버전으로 확장

### 14.4 투자 추천 오해

리스크: 지도에서 점수와 색상을 보여주면 특정 구를 추천하거나 배제하는 서비스처럼 보일 수 있다.

대응:

- “추천” 대신 “보류 사유”, “비교 필요”, “현장 확인” 표현 사용
- README와 화면에 투자 자문이 아님을 명시
- 점수는 의사결정 보조 신호로만 설명

## 16. 포트폴리오 설명 문구

### 한국어 설명

Redveil V2는 기존의 추상 리스크 그리드를 실제 서울 자치구 경계 기반 지도형 UX로 확장한 버전입니다. 사용자는 서울 리스크 지형을 먼저 훑고, 관심 구를 선택한 뒤 보류 사유, 대체 후보, 현장 확인 항목을 확인할 수 있습니다. 선택한 구는 매물 검토와 후보 비교 흐름으로 연결되어, 단순 점수 확인이 아니라 매입 전 의사결정 과정을 구조화합니다.

### 영어 설명

Redveil V2 expands the original abstract risk grid into a district-boundary-based map-first decision flow. Users can scan Seoul’s storefront risk landscape, select a district, review pause reasons and alternative candidates, and move directly into property review or candidate comparison workflows. The goal is not to recommend purchases, but to structure pre-purchase caution, comparison, and field-check decisions.

## 17. 최종 정리

Redveil V2의 이번 달 목표는 실제 지도 API를 붙이는 것이 아니라, 실제 서울 자치구 경계 데이터를 활용해 GitHub Pages에서 동작 가능한 정적 인터랙티브 지도 기반 의사결정 흐름을 완성하는 것이다.

이번 달 구현 범위는 지도 1~3단계로 제한한다.

- 실제 서울 구 경계 지도 적용
- 지도 클릭/hover/선택 강조
- 선택 구를 매물 검토와 후보 비교로 연결

장기적으로는 Leaflet, Kakao Map, Naver Map 기반의 확대·축소, 주소 검색, 매물 마커, 주변 상권 레이어까지 확장할 수 있다. 그러나 이번 V2에서는 포트폴리오 완성도와 현실적인 구현 가능성을 우선해, 정적 지도 기반 Map-first UX를 완성하는 데 집중한다.
